### 1.1 用途、成功目标及与F-2-6的区别〔R01〕

生成物是“正式权项全文＋技术骨架与回退依据＋当前支持核对＋修改对照/T6＋完整累计交接”。成功是范围有据、技术关系完整、策略与确认落实、改动可追踪、下游可继续完善说明书；不是权项数量、篇幅、格式或表格齐全。

| 维度 | F-2-6初稿 | F-4-11正式稿 |
|---|---|---|
| 目的 | 快速、低成本、可重复的方向探索 | 依据策略、支持和确认状态收敛正式表达 |
| 唯一前序 | Flow-1-5累计交底 | Flow-3-10累计沟通确认 |
| 方向 | 单轮主方向供后续比较选择 | 落实有效范围选择；未选择时给明确受限建议，不冒充批准 |
| 支持 | 区分交底依据与待Flow-2-7建立的支持 | 核对当前实际说明书，不能预借Flow-4-12未来支持 |
| 修改 | 初稿取舍、特征矩阵、T4初版 | 最终矩阵、T4更新、精确修改对照和T6初版 |
| 评价 | 探索有用且保真 | 正式表达、实际支持、策略落实、修改依据与交接可靠 |
| 消费者 | Flow-2-7说明书初稿 | Flow-4-12说明书正式稿 |

不机械要求正式稿比初稿更长、更窄、从权更多或所有内容重新生成。保留已有合理范围，纠正有行动价值的缺陷；不为了安全把有依据的概括一律限死实施例，不为了扩大范围增加无依据等同替换、变体、功能、关系或效果。

### 1.4 T5、技术确认与保护范围的落实〔R04〕

读取累计中的`technical_confirmation_matrix`、`effect_evidence_confirmation`、`confirmed_change_instructions`、`technical_evidence_gaps`、不采用内容、范围/回退选择及人工判断状态。对每个决定性修改指令，说明执行位置或不执行理由；不能以润色忽略其改变技术重心或保护底线的影响。

T5用于确定有依据的区别特征或相互作用组合及策略重心，不在本节点默认重做深度检索或完整创造性论证。范围改变时核对对应论证还能否成立；仅有新依据/明确修订时更新受影响关联并留旧值与理由，证据不足则标策略缺口，不复制旧T5结论到新组合上。最接近现有技术仍是候选建议，保留人工/审查判断状态，不以“正式稿”升级为已确定或授权保证。

明确区分技术事实、机理/效果证据、拟保护范围和提交选择的确认。笼统“全部同意”“请写得宽些”不自动确认具体参数、未知关系、实验或全部T5判断；只有可定位的明确确认及相应技术依据才更新`confirmed_fact`。用户认可某范围不创造说明书支持；有技术依据不冒充用户已选择该范围。

未选正式方向时，结合现有支持和策略提出一个明确标“待范围选择”的主候选，列决定性选择与影响，不静默替人批准，也不强制等人答完才能生成。只有用户要求多方案时显式分组，区分主候选与备选，不能拼成一套唯一提交文本。

<a id="business-1-5"></a>
### 1.5 独权技术骨架与必要特征组合〔R05〕

每项独权在分析区明确保护对象、主`tp_id`、完整必要特征组合及关联`feature_id`、技术作用、整体`te_id`与证据状态。正文以技术特征表达技术方案，不把分析区TP/TE表机械塞进权项，也不把纯功能、目标或预期效果当已完整手段。

核对元实体、连接、位置、依赖、交互、时序、输入输出、转换和必要步骤等实际关键关系，判断其如何共同解决主TP。检查删除某限定后是否仍形成可实施路径并取得所依据效果；不能为写宽遗漏已有必要关系。性质不同的方案分别明确边界，不能将各自有出处的特征任意拼成新组合。

关键关系已有而被本节点漏写，是生成缺陷；确实缺失则给有依据部分及明确标记建议/待补事项，不能虚构来凑完整独权，不能仅靠“请复核”宣告完整。独权必要性、方案完整性、技术作用和最终范围由LLM/人工判断，代码不能凭关键词数量裁决。

<a id="business-1-6"></a>
### 1.6 从权回退、正式表达与申请类型〔R06〕

从权应有实际附加限定、关联特征、技术贡献和回退目的；不按最低数量造参数或常识性装饰。没有有用从权可说明理由。按父项继承全部限定后核对新增限定与累计组合的相容性、作用条件、来源及支持；不能把从权独立看成一个孤立片段。多项引用采用择一分支核对，不混为同时叠加；多项从权不得作为另一多项从权的基础。

检查编号、在前引用、主题名称、权项类别、限定关系、同物同名、指代、连接/步骤顺序和简要性。附图标记若使用，与当前材料一致，不假称核验未读图像；不把分析说明或风险提示当作实际技术限定。独权表达依发明性质选择适当方式，不强制每件均写成同一“两段式”模板；多类别/多独权须有对应技术依据和单一性分析，不默认穷举。

发明与实用新型分别按已知保护对象检查；实用新型不得把纯方法/算法换名“模块”或虚构连接以宣称适配，材料有真实结构才据实表达。类型不适配或未定时保留技术内容、标明问题和人工选择，不自动改申请类型。范围层级不是越宽越好，也不是从权越多越好。

### 1.7 实际说明书支持、特征矩阵及T4更新〔R07〕

按本轮**当前实际说明书版本**逐权项、逐特征及组合建立最终特征矩阵和T4权项侧。继承支持记录只在仍与当前正文、说明书版本及来源对应时沿用；权项或说明书变了就核对受影响记录，不整表照抄“充分”。

| T4必备列 | 本节点要求 |
|---|---|
| 权利要求号/特征序号 | 对应本轮正文准确权项与片段 |
| `feature_id` | 对应当前T2；保留新增/修订映射 |
| 说明书支持 | 当前实际段落、实施例、附图或表格定位；可用准确章节/片段定位，不能伪造段号 |
| 技术作用 | 关联主TP、功能、效果和必要性；效果维持原证据状态 |
| 概括层级 | 具体方式、并列选择或上位概括，以及成立条件/边界 |
| 支持结论 | 充分、部分、缺失或建议限缩；写明关键依据和缺口 |

在同文件来源登记中关联输入ID、实际/继承哈希和定位。分别核对单个特征及其关系、父项累计组合、实施方式可组合性与效果成立条件；各自有出处不等于该组合已有支持。上位概括、并列替代、功能性限定、参数区间/端点与删除限定均检查其覆盖的方案是否可依据现有披露解决同一问题、取得相应效果，不能从孤立实例随意外推整个范围。

尚无当前说明书、只提供片段或只有交底时，标明交底依据与实际支持缺口，给有据限缩/表达建议和人工动作；**不能以“待Flow-4-12补上”宣称当前已充分支持**。Flow-4-12可依据已有技术内容完善表达，但不为无来源权项发明实施例。缺口保留在T4、风险、交付状态及完整累计中，持续输出不等于支持通过。

### 1.8 修改对照、范围影响及T6初版〔R08〕

本轮修改前基线是实收累计中当前有效权项。用户明确替换时，先记录该权项与替换版本之间的真实对照及范围影响，再以替换后版本开展后续修订，区分两段修改链并保留收到的有效历史；不能以选定替换稿为新基线来漏记替换本身。不是自动回读F-2-6旧稿，不把最早文本、参考答案或文件名相似稿当作对照基线。可定位修改前原文才称真实比较；若缺失，明示“修改前未提供/无法完整比较”，记录本轮有据内容和缺口，不虚构旧句，也不把新起草算已核验修改。

每项增、删、合并、拆分、关系/参数/类别变动及有意义的措辞变动，形成精确前后对照、来源、技术理由及保护范围影响；纯表达调整与实质范围变化分开，不能所有改动一律称“仅文字优化”。权项重编号保存前后对应关系，与正文、矩阵、T4及修改指令一致；无改动明确说明，不为凑表制造修改。

| T6必备列 | 本节点要求 |
|---|---|
| 修改对象 | 当前权项及准确片段；编号变动保留映射 |
| 修改前/修改后 | 可比较的准确原文/新文或范围变化；缺前文明确记缺失 |
| 原申请依据 | 定位实际依据并区分撰写来源与原始提交文本；不能以确认意见替代原申请披露 |
| 技术理由 | TP—手段—效果、策略、支持或确认指令的真实对应 |
| 超范围检查 | 明示适用阶段、所核原始文本及直接记载/可直接无疑义确定依据，或不适用/未验证理由 |
| 处理建议 | 可采用、需人工确认或不建议采用；与事实状态和范围影响一致 |

未提交申请时，T6首先是撰写修改来源账：标明尚未形成原始提交文件，不能把最初交底、F-2-6或F-3-10机械当作法定原申请范围，也不能宣布完成法律上的超范围判断。已提交申请的修改，法律边界取决于实际原始说明书及权利要求；当前文本、用户确认或后补实验不能取代该依据。原始文本缺失/不完整时标法律核查未验证，不回读历史文件、不新增强制业务输入；原始提交内容只能由累计或现有允许通道中实际提供的可核材料取得。

来源、支持或范围仍不成立时，不将该修改列为已确认推荐限定。可以保留明确标记的受限建议/不采用理由；不得因为存在风险就删除整个修改记录。T6初版仅权项侧，说明书侧留Flow-4-12更新，最终综合检查留Flow-5-13。
