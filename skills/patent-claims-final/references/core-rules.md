# 权利要求正式稿辅助独立规则

## 当前依据与确认
从当前权项、实际说明书/交底及真实确认或明确修订目标开始；独立模式新增disclosure_file/text通道，不借此改变旧链八输入表。核确认指向的精确版本/命题/范围，V1同意不能批准V2；事实、文字支持、范围选择与修改采用分别记录。无确认或原始申请，仍可有据讨论，不称可提交。确认当前技术也不能创造原始公开。
## 修订和完整布局
落实有源策略、必要组合、实体连接/位置/交互/时序/步骤、并列对象及从权回退；不因扩大范围无据增加等同替换、功能或效果。每项从权按真实父链核累计限定与互斥；概括和参数范围核已给实施与反例。重要独权、对象、联合回退既然决定纳入，当前权文应实际编号，不能仅在建议表声称覆盖。缺件明确作用，不用“正式稿”名称升级状态。
交完整修订权项、独权问题/必要组合/作用/效果、从权增量及范围代价、最终特征矩阵、T4权项侧、逐修改旧新文/理由/来源/影响和本次T6。每一新增限定及组合核实际说明书/原始依据；无原始材料不作修改合法性通过。局部润色同样核全部受影响真实子路径、条件与逻辑，未改支路保留。默认单轮有限修订，不自动重跑或替用户作最终选择。

## 详细规则与自检

按[授权技术条款](business-rules.md)逐项核技术链、条件、范围、来源和对应成果；其中旧输入/历史治理不成为独立前置。交付前对照实际材料核所有重要对象、关系、数值、逻辑、实施路径、效果证据、支持/引用、人工改动、未读范围与全部开放警示。可在本次授权内修正生成遗漏，不能把本轮漏项推成用户缺件。自检、独立审阅、技术确认、专业接受、可提交各自留证，不用格式、分数或保存成功代替内容判断。

## 表字段

按[本节点技术表字段](table-contracts.md)组织实际职责内的T表/支持记录；不提前生产未到本节点的表，不填空表冒充完成。
