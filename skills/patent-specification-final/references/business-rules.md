### 1.1 用途、目标与责任分界〔R01〕

`spec_final`是以Flow-4-11正式权项及其累计快照为基线，结合本次明确用户补充形成的**说明书正式稿、摘要及完整累计交接报告**。读者是用户、专利代理师和Flow-5-13终检节点。目标是可编辑的完整正文、可定位的逐权项支持、能够实施的技术公开、与依据匹配的概括及效果边界，以及不丢失的来源和警示。

F-2-7主要用于快速试写和方向选择；F-4-12不能以“便于讨论”代替上述正式稿实质目标。没有材料支持的地方不得伪造，仍须交付已有技术内容、缺口和受限状态。**持续输出、生成合同符合性和正式稿技术成熟度是不同判断**：带警示生成可以符合流转合同，但决定性公开、支持或范围缺陷不会因为已披露而消失。

本节点不重新选择保护方向、不主动重写正式权项、不开展新的全文检索，不替代F-5-13终检、新颖性/创造性判断或最终提交确认。继承T5及前序确认结果，说明其来源和未确认边界；不把继承结果说成本节点已经复检。用户或专利专业人员负责关键技术事实确认、保护范围选择、前序返工及正式提交文本确认。

### 1.4 正文、摘要及可编辑性〔R04〕

`## 核心结论`简述基线、完成范围、最重要的公开/支持结论、模型补齐范围、开放风险和是否建议流转或直接提交。不以“正式稿已完成”遮盖受限状态。

`## 核心结果`中的说明书应有实际全文，而非只有模板、清单或概括。按名称、技术领域、背景技术、发明内容（实用新型用相应名称）、附图说明、具体实施方式组织；有实质理由采用其他顺序时说明理由。正文业务子标题置于三级或以下，不新增主Markdown顶层章节。

| 内容 | 生成与核对要求 |
|---|---|
| 名称及术语 | 沿用当前技术对象和术语；缺失则标暂定，变更记录对应关系，不凭名称新增方案 |
| 技术领域与背景 | 写实际方案所属领域及有来源的缺陷/原因；背景文献依据来自实收证据，不编造公开号、全文读取、检索或“所有现有技术均无效” |
| 发明内容 | 说明技术问题—方案/特征组合—作用机理—有益效果的对应关系；不只复制权项，不使用宣传式保证或未经证实的排他结论 |
| 具体实施方式 | 展开理解和实现所需的实体、关系、步骤、条件及边界；可用材料支持的内容实际写出，不用“按常规即可”掩盖决定性缺口 |
| 附图说明 | 与实读图号和标记对应；无图或不可读时明确状态和必要附图计划，不虚构图内信息 |
| 摘要 | 包含名称、领域、技术问题、方案要点及主要用途，以技术方案为主，与正文范围和证据强度一致；不增加新事实或效果，不用商业性宣传语 |

正文用规范、清楚的技术语言，不能用“如权利要求……所述”一类引用替代实体技术说明。标准中的权项/段落关联检查是报告分析，不是把此类引用写入说明书正文。

摘要正文文字部分（包括标点符号）不得超过300个字；本报告定位它所用的三级标题不算摘要正文的提交内容。附图标记按摘要要求表示；有图时给出来自实际说明书附图的摘要附图建议及选择理由，图未提供时只列计划和缺口。摘要不含尚未成形的完整方案时如实受限，不能靠删关键技术关系满足字数。字数观察不代表正式排版、请求书指定、清晰度或申请系统验收已经完成。

### 1.5 可实施公开及领域适配〔R05〕

至少检查一条来源可追溯的完整实施路径，从对象/输入，经必要实体或步骤、关系、条件及控制，到输出/效果。存在多套需公开的方案或并列选择时逐一检查，不能用一条路径的存在证明全部范围都可实施。不规定固定实施例数量、最低字数，也不默认所有申请都需要实测；需要什么内容取决于本方案是否可由本领域技术人员实现并取得所述效果。

| 领域/条件 | 按实际需要展开，不作跨领域强制空表 |
|---|---|
| 结构、电气、机械 | 组成、连接/位置、运动与传力/导电关系、装配或操作、关键配合和环境条件 |
| 控制、通信、数据处理 | 输入输出、状态、依赖/时序、变换规则、必要控制条件和异常/边界处理；不把功能愿望当可执行步骤 |
| 软件/AI | 算法与具体场景的技术关系、输入输出及其关联；涉及模型构建/训练时核对必要模块、层级、连接和训练所需步骤/参数，不虚构架构、数据或训练结果 |
| 材料、化学、工艺 | 必要组成及范围、制备/处理顺序和条件、可获得/识别方式、用途及支撑效果的依据；不凭经验造配方、样品或验证数据 |

本表是技术公开检查入口，不替代专门领域的完整法律审查。序列、生物材料等特殊对象材料缺口应披露并建议专业核对，不制造保藏、序列表或实验合规证明。

可实施性矩阵逐方案/路径列：方案及相关稳定ID、实体/步骤及元关系、必要条件、对应正文定位、来源和可信状态、可实施判断、决定性缺口与影响、建议确认/修订动作。不能形成完整路径时模型可补齐合理解释，但新增事实保持待确认；说明受限稿的边界，不能报告已完成充分公开。

### 1.6 权项支持、概括与效果边界〔R06〕

**完整T4覆盖全部当前独权、从权及技术特征，不抽样。** 列保留：权利要求号/特征序号、`feature_id`、说明书支持（当前段落/实施例/附图/表格定位）、技术作用、概括层级、支持结论（充分、部分、缺失或建议限缩）。定位须能在本次当前文本找到，不能凭同词出现、附图计划或旧“充分”标签判定支持。多个特征确共用位置可以共用定位，但逐特征对应清楚；必要ID缺失如实登记，不假造前序已生成的ID。变更正文后重新回查受影响项。

概括范围测试至少列：权项/特征、上位概括/功能性限定/并列选择/参数范围、来源支持的代表实施方式、解决同一问题与取得同类效果的依据、已知失效或未知边界、判断和修订建议。一例并不自动支持全部上位范围；也不因为没有固定数量的实施例就自动判不支持。不能通过虚构替代方式或试验补齐范围。

效果证据矩阵至少列：`te_id`、关联`tp_id`与`feature_id`或组合、作用机理、成立条件、指标/单位与测量方法、证据来源及定位、证据状态、与本稿表达的一致性、缺口及动作。区分实际试验、仿真、计算、文献直接记载、合理推导和待验证，不把文献数据说成本方案实测，不跨对象/条件套用；已知单位/参数矛盾不得静默纠正。

无实测不是所有领域的自动失败条件；但决定性条件或效果仅凭愿望、关键因果关系无依据而不能支持实现时，必须列为实质缺口。保留真实未知，不虚构数值和成功结论。机理分析不自动等于已验证效果。

<a id="business-1-7"></a>
### 1.7 附图、说明和标记映射〔R07〕

图文映射逐实际/计划图列：图号、实读或计划状态、标记、元实体/关系及稳定ID、正文位置、对应权项/路径、来源及问题。检查同一组成部分标记一致、文字与图中标记对应、术语及方向一致；只有文件名或文字说明不能证明读取过图内结构。实际图未读或分辨率不足时记录无法核验，不编图号/坐标/细节定位。

发明的附图必要性依理解和实施需要判断，不能一律无图即失败；若缺图使关系不可理解，具体说明缺什么。实用新型正式提交需有表示所保护产品形状、构造或结合的附图，缺失时仍生成受限稿，但附图计划不能冒充已满足正式附图要求。申请类型未定或冲突保留原状态，分别说明受影响检查，不静默指定类型。

### 1.8 来源、合理补齐与无来源新增〔R08〕

每项来源登记保留`content_id`、`content_origin`、`source_input_id`、`source_locator`、`source_hash`、`trust_status`、`last_updated_flow`、`revision_reason`。来源定位只用本次实际可读证据。可信状态为`source_fact`、`confirmed_fact`、`reasoned_inference`、`hypothesis_to_verify`或`excluded_from_formal_text`；内容来源区分`upstream_snapshot`、`user_file`、`user_text`、`workflow_analysis`、`model_completed`、`human_confirmed`。

`source_fact`只说明材料直接记载，不证明实验真实或技术一定成立；`confirmed_fact`须有对具体技术内容的明确确认和来源，不由模型置信度、生成次数、选择方向或接受风险推出。保留原有确认对象及范围。

每项模型补齐记录`content_origin=model_completed`、`completion_basis`、`assumptions`、`confidence`、`affected_section`、`human_confirmation_status`，并在其出现的发明内容、实施方式、摘要、图文/支持表等位置显露“合理推导/待确认/候选表达”或关联内容ID。不只在末尾写泛化免责声明；同一不确定内容跨章节标记不消失。

有技术依据、合理且与当前方案一致的解释性补齐可进入标记明确的待确认稿，不仅因含推导就判为生成缺陷。标注不是免检：不合理、与输入矛盾、改变发明点或引入无依据实体/关系/参数/步骤/变体/工艺/控制/效果者，不得构造成已确定正式方案。完全无技术依据的新设想列为未采纳建议或问题，标`excluded_from_formal_text`，与正文有效技术内容分开；不得靠“待确认”包装无依据发明。补齐、无来源风险和剩余技术缺口各有定位和确认动作。

### 1.9 修改前后对照与T6说明书侧〔R09〕

对本次实际修改列：修改对象/位置、修改前后精确文字或范围变化、技术理由、来源/输入ID与定位、受影响权项/稳定ID、修改依据判断、处理建议和确认状态。只重排或措辞变化也记录不影响含义的理由；没有可读修改前文本时说明“修改前缺失”，不编造差异。不因本次未改而伪造修改项。

T6保留上游权项修改依据，并更新说明书侧，列包含修改对象、修改前/后、原申请依据、技术理由、超范围检查和处理建议；同一对象多次修改保留来源及前后关联，不把旧版删除。明确区分：

- **申请前准备**：记录交底/当前材料的技术来源与修订依据，不能把这些材料冒称已提交的“原申请”。
- **已提交申请后的修改**：原说明书和权项内容/定位必须已在实收累计快照或本次允许材料中可读，并明确其提交文本身份；按直接记载或可直接、无疑义确定检查。只有新增客户补充、后做试验或当前草稿不能自动证明原申请已公开。
- **基准缺失/身份未明**：T6记录无法核验、缺什么依据及人工动作，不判定“不超范围”，也不因此回读历史文件。原申请身份未确认时不伪造肯定法律结论。

摘要是技术信息概要，不能单独作为以后修改说明书或权利要求书的原始公开依据，也不能据摘要解释保护范围；T6不得把仅在摘要中出现的内容当作原说明书/权项已有支持。

处理建议为可采用、需人工确认或不建议采用；建议范围与当前来源强度一致。正式修改决定留给用户/专利专业人员。
