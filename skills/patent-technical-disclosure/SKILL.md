# 技术交底整理

直接接收普通研发材料，写出用户能够核对、撰写者能够继续使用的技术交底。默认独立使用，不要求先运行其他Skill、填写专业T表或提供前序文件。

先读[独立输入输出合同](references/standalone-contract.md)和[交底规则](references/core-rules.md)。材料存在时实际读取；缺关键结构、图或实验只限制对应结论，仍交付有用的已知部分和具体追问。

## 输入与模式

一项连贯研发说明即可开始。技术说明、附图／图中关系、实验／计算数据分别保留实际文件或文本身份。多个独立材料不能混成一个虚假来源；用户无需理解这些登记字段。

只有实际传入累计主Markdown并要求接续时，读取[链式适配](references/chain-adapter.md)。独立模式没有缺前序警示、伪造上游UID或历史T表；真实技术证据缺件继续如实保留。

## 工作与结果

1. 识别技术对象、问题、主方案、备选和实际申请类型；主线未选时分别整理，不替用户选赢家。
2. 写清实体／步骤、连接、交互、时序、触发条件、输出及效果路径；未知机理和实现条件明确待核。
3. 形成完整交底正文、实施路径、T1问题表、T2要素表、T3效果表、图文／术语映射和来源记录。冻结表示本次身份稳定，不表示已确认技术或已验证效果。
4. 同一文稿先给易读结论，再给准确技术说明与能逐项回答的确认问题；不让用户填专业表，也不提前代写权项、T4、T5或T6。

输出五章及保存约定按独立合同执行。交付前核对参数单位、左右／连接、逻辑“且／或”、时间与状态、图号标记、来源和所有未决项；需要检索或实际工具时按任务范围使用，不编造调用。

[限制与验证范围](references/limitations.md)说明未证事项；来源核对时查[来源说明](references/sources.json)和[规则采用映射](references/rule-map.json)。不因文稿、工具或结构检查成功宣称专业接受、技术可实施性已证或可直接提交申请。
