### 1.1 用途、读者与成功目标〔R01〕

`patent_plan`是在F-3-8全文深度复检累计基线之上形成的**保护范围与创造性论证计划、说明书加强计划、发明人行动建议及完整累计交接**。它不重新代替全文检索，不直接生成正式申请文件；作用是把专业复检转化为后续确认和正式撰写的可用方向。

读者有三类：发明人需要读懂“保护什么、为何这样写、我要补什么、补完往哪里走”；专利专业人员需要可核实的范围取舍、证据及论证主线；F-3-10需要逐项可确认的事实、机理、数据和范围选择。三类内容放在同一主Markdown，不拆成彼此失配的通俗版与专业版。

成功不是术语多、篇幅长、警示少或承诺授权，而是：建议贴合本轮技术与文献；技术对象和关键关系不失真；每个重要结论有依据及强度；发明人知道可执行的下一步；专业人员能够核对并决定范围；下游只读本文件也不丢有效内容。资料不足但边界清楚的受限计划可以有用。

### 1.2 技术建议与人工责任边界〔R02〕

本节点提供技术内容与撰写准备建议，不评价权属、优先权、首次公开、申请时机、费用或期限；不代替用户、专利专业人员或审查员作最终保护范围、最接近现有技术及创造性判断。用户策略只表达目标与偏好，不产生技术事实或人工确认。

`application_type`继承当前累计快照或已有明确配置，只用于内容适配；类型未定/冲突时列出影响，不静默猜成发明或实用新型，不增加必填输入或推荐程序性类型选择。程序问题如被提出，说明本轮不作该决定，列为需另行处理的问题，不据未知程序事实给出结论。

不输出授权概率、保证授权、检索无遗漏、法律上必然无新颖性/创造性等结论。也不把本计划、方向选择、机器结构检查或“已生成文件”称为正式提交合格认证。涉及新颖性/创造性的技术风险分析必须带证据范围，不将技术材料适配自动提升为文献的法律时间资格。

### 1.7 深入浅出的表达合同〔R07〕

采用**先讲人话，再给专业依据**：先以本轮具体技术对象讲清意义，再在专业表中给特征ID、权项、文献或说明书定位。术语首次出现须解释，例如独立权利要求是“一项完整方案的基本保护范围”，从属权利要求是“在基本方案上增加具体限定的保护层级”，回退路径是“较宽方案遇到风险时，有依据地增加哪些限定”；T5是“逐项解释技术差异、效果及为什么不容易从已有技术得到的论证表”。后续保持同义，不反复复制术语教学。

不能为通俗而丢掉条件、关键元关系、相互作用、来源及警示，也不能让通俗层声称“已证实”而专业层写“待验证”。比喻只能辅助解释，不能引入新的技术实体、参数、关系或效果。专业附表不能代替发明人行动建议，通俗摘要也不能代替完整累计快照。

重要建议尽量用短句和有因果联系的段落，让发明人不必靠猜测知道应提供什么。避免只有“加强创造性”“完善实施例”“尽快申请”“请人工复核”。不规定统一字数；简单问题从简，复杂问题保留必要解释。

<a id="business-1-8"></a>
### 1.8 保护主题与必要技术组合〔R08〕

按拟保留的每项独权主题说明：技术对象及主TP，完整方案的实体/步骤/数据与关键连接、交互、时序或因果关系，必要特征组合、对应效果和依据。必要性根据解决当前技术问题的作用解释，不能靠特征数量、行业词汇或“更创新”形容词判断。

向发明人说明“为什么保护这组关系”“删掉某项可能失去什么”“哪些是必需、哪些是优选或可讨论替代”。不把全部实施细节机械塞进独权，也不为追求宽删掉已知关键关系。存在多个主题时说明相同/相应技术贡献、相互关系和待专业人员判断的组织问题；不扩展为程序性拆分申请决定。

按实际领域适配：机械关注实体及配合/动作，软件控制关注输入—处理—输出、状态及反馈，材料化学关注组成、结构、制备条件和效果依据；不要求每个领域填写所有类别或强塞硬件、剖面图、实验数量。

<a id="business-1-9"></a>
### 1.9 范围层级与有依据的回退链〔R09〕

逐主题分析宽、中、窄权项及从属回退层级。每层至少写清拟保护/排除对象、必要组合、相较前层增加/保留的限定、技术作用、来源及说明书支持、收益与代价、风险和人工选择状态。可以用关键拟限定及范围表达说明层级；不强制生成三套完整权利要求，但不能只贴三个标签而没有实质取舍。

上位概括、并列选择、功能性限定、替代方式或参数范围要说明成立边界；范围偏好不能创造支持。如果无法形成三个实质不同且有依据的层级，明确哪些层级不成立、为何、需补什么，而不是编造限定凑数。每级从属回退要有真实附加限定及贡献，避免同义词重排。

范围更窄不自动意味着更有创造性或支持充分，特征更多也不自动提高结论强度。无来源新增特征/区间不得作为可直接采用回退；可讨论设想应标明待验证并与已支持路径隔离。保护范围最终由人选择，不能因为模型推荐把人工判断栏改为已确认。

<a id="business-1-10"></a>
### 1.10 全文复检证据与新颖性风险的消费〔R10〕

基于实际累计快照消费F38的文献表、逐权项/特征组合证据矩阵、效果对照、最接近候选和检索缺口，并用本轮实际补充更新相关分析。区别文献直接明确公开、可直接无疑义确定、已读范围未见及未能核验；名称相似或摘要相关不能代替结构/关系/手段/效果比较。

如果单篇文献对推荐独权的完整方案覆盖有风险，先说明对应证据及对范围计划的影响，不绕开该风险仅谈多文献创造性。不能把多篇拼接当成单篇完整公开，也不能把“本轮未找到”写成整篇未公开或检索无遗漏。全文、关键附图、翻译或来源时间资格欠缺时列出受限边界和具体补核动作，不把技术比对结论升级为法律现有技术认证。

本节点不自动补检或回到F38；必要时列明人工补检/复检建议及预期改善。

### 1.11 创造性主线与T5〔R11〕

先用连贯文字向发明人解释：已有技术怎么做 → 本轮方案哪里不同 → 这些不同如何一起起作用 → 带来什么效果 → 已有技术是否指引这种组合，依据及反向风险是什么 → 还缺什么依据。再形成逐独权、逐相关候选的T5，不用一句“非显而易见”代替论证。

T5必备列及含义：

| 列 | 要求 |
|---|---|
| 权利要求 | 被评价独权/范围候选，能关联当前权项与特征ID |
| 最接近现有技术候选 | 候选身份、建议、接近理由、证据、置信度和人工判断状态 |
| 区别特征或组合 | 具体差异及相互作用；不得任意拆散协同组合 |
| 区别特征产生的效果 | 对应申请技术内容、机理、条件及证据状态 |
| 实际解决的技术问题 | 由已能获知的效果客观提出，不含区别特征本身或对它的暗示 |
| 技术启示分析 | 结合动机、实现路径、成功预期、技术障碍及证据/缺口 |
| 结论强度 | 强、中、弱或证据不足，说明理由、影响和待核实处；不是授权概率 |

最接近现有技术尚未经人工最终判断时保留多候选T5，不强行唯一化；按技术问题、整体方案及效果说明候选接近理由。候选数量由有效证据决定，不要求穷举或无限扩张。

区别特征效果须能从当前申请技术内容获知；输入没有的效果、机理或数值不能作为确定性创造性依据。合理推导保留条件与确认状态；提出的新问题不得偷带拟采用手段。客观问题重述应保留T1原始问题的来源与修订理由，不无声改写历史事实。

技术启示分析针对整体方案与具体相互作用：比较文献中的作用、组合动机/兼容条件、实现是否需要额外改造、是否有合理效果预期与障碍，区分已有记载与分析推导。不能仅凭“各部件都常见”否定整体，也不能凭“组合未逐字出现”肯定创造性；常识及结合动机缺证据时明确缺口，不编造公知常识。

### 1.12 说明书加强与支持性计划〔R12〕

针对每个推荐范围、关键区别组合和回退限定，定位当前说明书段落、实施例、附图/表格及来源；利用T4标明支持充分、部分、缺失或建议限缩，并解释影响。拟加强项目写清修改对象、要讲明的技术关系/步骤/条件、已有依据、待补资料和验证完成标准；不在计划中伪称正文已改、图已制作或实验已完成。

优先补足能让本领域技术人员理解并实现的连贯路径：对象/输入，必要实体或步骤及关系、作用过程和成立条件，输出/效果。图、操作记录、工艺说明、计算、仿真或实验按真实缺口选择，不固定实施例数量、附图数量或必需实验数据。没有实测数据不当然否定可撰写性；关键定量效果、参数边界或比较结论需要证据时，不能用漂亮解释顶替。

拟验证建议说明目的、对象、条件、对照（若需要）、指标/单位或观察方法及预期能回答的问题，结果保持待取得；不凭空设定目标值。补充内容需要与原技术来源关联，不能为覆盖更宽范围而生成无来源变体。已申请文本的修改依据问题如实际出现，明确依原申请公开范围由专业人员判断；本节点不替代F411/F412的T6，不把申请前补充讨论视为可直接用于申请后修改的依据。

### 1.13 具体可执行的行动建议〔R13〕

每项影响范围、论证或正式稿方向的重要建议，都须让读者获得以下信息；可用短段落或紧凑表格表达，不要求强塞七列格式：

**建议做什么 → 为什么重要 → 对应权项/特征 → 现有依据或缺口 → 请谁提供什么 → 完成标准 → 优先级。**

- 动作写明确交付，如某处图示、一次操作记录、某组已有参数/条件、某段机理解释或特定范围选择；不是“补全材料”。
- 责任人使用发明人/研发人员/制图人员/专利专业人员等角色，不编造具体姓名；技术事实由了解技术者提供，范围及论证由专业人员结合材料判断。
- 完成标准是可核验的材料、定位或回答及其一致性，不以“发明人说没问题”“模型评分高”代替依据。已有充分材料时建议核对/确认，不重复索取。
- 优先级分“先解决影响主线的问题”“正式稿前完成”“可选增强”，说明依赖和拖延影响；不虚构日期、期限或必须等待一切材料齐全。
- 指出材料到位后下一步谁处理、进入哪个已存在阶段；未解决时给有依据的替代/限缩或受限使用建议，不自动调用节点。

表达示意（假设片段，非真实样例或技术事实）：若已有材料显示两部件配合，但连接被遮挡，可建议“请补一张能看清该连接的剖面图，并说明工作时是否相对运动；这能帮助撰写人员把关键配合关系写清楚。完成标准是图、文字和同一特征ID一致；确认前相关限定继续待确认。”实际技术不需要剖面图时不得套用。

### 1.14 后续撰写与申请技术准备建议〔R14〕

基于具体缺口而不是模板判断，分别说明：

| 情形 | 给发明人的建议 |
|---|---|
| 可进入正式稿撰写 | 说明已有哪条有依据的主线/范围可用，哪些事项仍需F310确认、正式稿及终检；不说可直接提交 |
| 可继续撰写，但需先补关键材料或作范围取舍 | 指定依赖、所需返回材料、受影响权项及完成后动作；未解决时说明范围/论证使用边界 |
| 当前材料不建议直接用于提交 | 定位会影响完整技术方案、公开充分、支持或关键效果依据的具体缺陷，给补救路径；仍允许带警示流转 |

多主题存在不同情形时分别说明，整体建议不能遮住受影响独权。说明建议的证据边界：它是技术内容使用建议，不是授权保证、程序性申请安排或正式提交合格认证。不能把未确认的关键假设当事实建议直接提交，也不能仅因缺实验而一律禁止撰写。

后续顺序以现有链说明：先经F-3-10确认本轮问题与范围，再据确认形成F-4-11权利要求正式稿、F-4-12说明书正式稿，最后由F-5-13做申请文件终检。需要前序补检、补事实或重拟方向时列人工返工建议；这些动作尚未发生，不自动触发运行。

### 1.15 F-3-10确认清单与人工判断栏〔R15〕

逐项列需要确认的技术事实、必要关系、机理/条件、效果及数据、参数边界、替代方式、范围层级/回退选择和最接近候选判断。每项能定位到`tp_id`、`feature_id`、`te_id`或具体权项/来源，并写清可回答的问题、需返回的材料/依据、影响与当前确认状态。

每项确认问题只对应一个可独立回答的技术判断；同一`feature_id`下可分别确认的关系、机理、条件或效果须拆成独立问题，各自保留回答、依据和状态。可以共用图或记录，但确认其中一项不代表其他项也已确认；部分回答只更新所覆盖事项，其余保持待确认。索取支持该判断的图或记录不必另拆为一个技术判断。

事实问题问“部件是否保持固定关系、图或记录在哪里”，而非“整篇是否没问题”；范围问题问“选哪一级、为何、接受何种覆盖取舍”，不把范围偏好视为事实确认。把发明人核实技术理解与专业人员判断候选/范围分开。无人回答或只有笼统认可不升级`confirmed_fact`；已有明确确认继承来源及状态，但不据本轮建议新增确认。

人工判断栏保留候选/范围建议、判断主体、状态与依据；尚未判断标待确认。F39不提前生成F310的`technical_confirmation_matrix`已确认结果或正式修改指令。行动项可在本文件编号以便沟通，但不新增下游必填字段、不改变F310输入合同，不要求额外并行文件；下游仅靠本文件即能建立确认矩阵。
