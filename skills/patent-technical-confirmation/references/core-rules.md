# 逐项确认规则

OasisIntWrite于2026-11-07根据自有F-3-10 V0.1.1改编；独立输入／输出由本包新合同定界，不提升原草案效力。

## 从原话到技术命题

逐条保留opinion_id、实际原话／材料片段、输入ID、页／段／图／句序及原始哈希；一条涉及多事项可拆子项，但不能去重掉冲突。原话定位指向实际输入，规范表述定位指向当前结果，两者不能互换。每条规范技术表述必须另给当前主MD内的精确定位、该规范表述片段SHA-256及其截取字节约定；原话片段也独立给定位/hash/字节约定。不能用整份输入哈希或原话哈希代替规范片段哈希。片段哈希说明原字节截取约定，不用模型生成的新句子代替原话证据；整份结果冻结后的哈希放实际调用记录，不回写自身造成循环。

分类可包括事实确认／纠正、补充、机理、效果、范围选择、表达偏好、拒绝或未回答；分类不替代判断。优先关联已有tp_id、feature_id、te_id和问题ID。没有旧ID时明确新建，不冒充继承，不静默重编号。

将口语整理为明确的对象、动作、关系、条件与结果；不强求每句话凑齐五项。否定、可能、暂定、未试验、特定工况、顺序、左右、数量和单位均保留。存在多个解释就分别写候选表述、歧义和消歧问题，不选择最有利于保护的版本或用“等同方式”扩展。

反馈者及时间只有实际提供才登记；未知保持未知。没有真实反馈时可形成追问清单，不能由模型代答或写已沟通完成。

## 基线、确认与支持分开

保留实际基线及反馈的不同来源。反馈“不是A是B”且与有效基线冲突时，先列差异和拟修改；运行指令没有准确覆盖对象与范围时，不自动以B删除A。非冲突解释可以据实际材料补入；明确授权只改指定工作稿内容，不改历史原件或原始申请公开。

具体确认仅覆盖实际答复到的命题及条件。看懂、整体同意、接受风险、希望范围更宽或未回复不确认整稿、效果或所有替代方案；有支持也不表示本轮已确认，未确认也不表示现有材料必然不支持。

涉及说明书支持时，T4支持结论仅使用充分、部分、缺失、建议限缩，并说明实际位置、支持的具体关系／概括层级和不足。确认状态、trust_status和待处理进展另列；不得用pending代替T4支持结论，不能把“未回复”机械变成“缺失”。未提供所需说明书时说明该支持判断未核，不虚构定位或充分结论。

## 效果、范围和证据

每项效果关联te_id、问题、特征／组合、机理、条件、边界、指标／测量方法及证据。数据区分实验、仿真、计算、观察、文献和期望，保留对象、条件、方法、单位、对照、结果及局限。一种工况不推广全部范围，仿真不改成实测，没有数据不编百分比、范围或最优点。

无实测不等于所有技术事实不可用；已有来源的结构和条件可作为受限撰写依据，效果仍按真实证据状态。发明人对机理的解释不自动成为试验验证。

范围／回退和最接近文献的选择另记人工判断状态。覆盖所有方式是偏好，不证明所有方式均可实现或受支持；新替代结构、材料和算法须核具体内容、同问题／效果关系和当前支持，不能以确认会议补造原始公开。

## 输出及修改指令

核心结果包含六组内容：technical_confirmation_matrix、effect_evidence_confirmation、confirmed_change_instructions、technical_evidence_gaps及不采用内容、人工判断状态、未完成确认与模型补齐。不存在的组明确说明本次没有相关材料或不适用，不保留无解释空表。

每条修改指令写明instruction_id、关联意见／内容ID、当前原文或准确定位、拟改具体文字／动作、依据、采用条件、受影响权项／章节／T表、范围代价和警示。表名不表示每条建议均已确认；待确认的指令写条件，不作为已采用修改。删除时保留不采用内容及重新采用条件。

追问包含当前具体理解、所缺事实、为何影响后续、希望返回的材料；优先关键关系、机理、效果条件和冲突。不要求发明人直接判创造性，不以诱导性问法将模型假设包装成确认。

只更新反馈实际影响的T1问题、T2关系、T3效果、T4支持或T5论证，其他有效内容保持。缺旧T表时可直接组织本次确认，不伪造旧表已存在。当前不生产T6。下游在同文件取得完整基线、准确原话、结果、条件指令、来源和全部警示，不能只剩意见摘要。

## 使用与自检

反查每个确认结论是否有真实具体答复，每条规范表述是否保留条件，每项支持是否独立于确认，每条指令是否有准确对象及采用依据。关键关系／效果／修改依据未知时允许受限建议，明确影响和不建议直接提交的原因，不自动运行或改写其他节点。
