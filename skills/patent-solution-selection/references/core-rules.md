# 技术方案筛选独立规则

## 比较与决定
至少两候选及同一目标做比较；只有一个时交single_solution_diagnosis，不能虚构备选或用户选择。保留每个实质候选、ID、互斥关系、主备/暂缓状态。按问题—必要组合—作用路径—效果依据、工程条件、硬约束、资源与范围代价比较，不编实验或统一数值排名。
逐候选说明技术价值、至少一条路径是否成立、缺哪些配合/条件。区分独权必要、从权优选、替代和实施例细节，结合实际申请类型。摘要只作线索；未提供全文或风险评级，风险保持未知仍可受限比较，不能将相关性改名为风险。
## 输出
交有条件主选建议、备选、暂缓/淘汰理由、全部候选处置，说明何证据会改变建议。真正决定者未选时标未决，不能擅自冻结最终主线或合并互斥发明。冻结只固定当前候选身份，不等于技术确认。交候选T1/T2/T3、实施和验证缺口及下一交底重点，不代写完整申请。

## 详细规则与自检

按[授权技术条款](business-rules.md)逐项核技术链、条件、范围、来源和对应成果；其中旧输入/历史治理不成为独立前置。交付前对照实际材料核所有重要对象、关系、数值、逻辑、实施路径、效果证据、支持/引用、人工改动、未读范围与全部开放警示。可在本次授权内修正生成遗漏，不能把本轮漏项推成用户缺件。自检、独立审阅、技术确认、专业接受、可提交各自留证，不用格式、分数或保存成功代替内容判断。

## 表字段

按[本节点技术表字段](table-contracts.md)组织实际职责内的T表/支持记录；不提前生产未到本节点的表，不填空表冒充完成。
