# 专利制图—编辑合同 V0.2.1

## 十字段编辑合同

向编辑工具传递以下自然语言字段，值取自实际原图及用户指令；不存在的要求如实写未指定。

```text
编辑强度：轻度 / 中度 / 深度，按实际内容确定
图像类型：照片、产品图、流程图、机械结构图、层状结构、文本截图等实际类别
用户明确要求改变：对象、目标变化和作用区域
必须保持：其余主体、结构、布局、编号、箭头、视图和含义
数量/结构硬约束：全部明确数字、数量、编号、层级、位置、方向和连接关系
多区域同步要求：需要同步的总览、剖面、局部、流程分支和前后状态
允许新增：用户明确允许或要求新增的内容
禁止新增：不在改变范围内的对象与该图类无关的元素
最终编辑指令：可执行的目标变化、保真要求及重要约束
尺寸/比例：实际指定值；未指定时保持原图可获得的尺寸/比例
```

合同是给工具的操作依据，不要求用户阅读或填写。一次只对准本次实际目标图及指令，不把历史对话的未确认修改自动带入。

## 修改强度与优先级

轻度：颜色、背景、清晰度、风格、去噪、线条、白底化、锐化或尺寸比例。

中度：布局重组、视图优化、局部强化、排版及流程重排。

深度：新增、减少、替换、数量或层级改变、部件/节点重排、结构与连接关系改变。深度任务的验收点是目标结构确已改变，不能只用清稿、增加编号或换色替代。

用户明确改变的内容优先于默认保持；未在修改范围内的内容保真。把“从6个改为8个”“左改右”“两层改三层”等目标原样保留；相关视图同步反映，不只在一个角落加符号。

## 类型规则

- 流程/逻辑图：保留未改的节点含义、方向、判断及反馈；只增加明确要求的新节点。主流程、分支和反馈的重排分别说明。
- 机械/装置/专利线稿：保留未改的视图数量、比例、数字编号和引线；局部图、装配和运动表达清楚，避免无关装饰、重叠虚影或将结构美化成另一技术方案。
- 层状/电路板/平面结构：数量、层数、接口、端子、路径和走线修改同步到总览、剖面和局部；不强制变为机械轴测图。
- 照片/产品图/海报：按用户要求修改背景、风格、色彩、光影、材质和比例；其他主体和构图保持，不套用黑白技术图限制。
- 文本/表格/界面：保持未改的文字含义、表格结构、层级及阅读顺序；检查实际文字可读性，不将伪文字视为完成。

## 调用与核对

查看实际目标图，选当前可用编辑工具，遵循其参考图传递机制；不得只给描述而不传目标图。需要多张图时准确说明每张角色；工具不能接收全部目标时先解决缺件，不偷偷丢图。原有透明背景默认保留，除非用户要求更改。

返回后对照原图查看：指定区域是否完成、未改区域是否保真、数量/层级/方向/关系是否正确、视图是否同步、编号及文字是否仍可读、尺寸比例和透明背景是否符合。实际不能判断的项列未核，不凭接口成功宣称内容通过。

本版不需要旧Dify应用或Gemini/GPT插件凭据。工具缺失则交上述编辑合同；缺原图则先索要原图。用户另行明确选择“从零生成”时才走新图生成分支，并把结果如实称为新图。

结果记录按[共用结果合同](result-contract.md)。超时未知使用`status=pending_verification`及`tool_status=unknown`，保留实际原任务/调用身份；成功但产物不可访问保持`tool_status=succeeded`并记`artifact_status=unavailable`，核同一产物，不重新改图。只有明确失败才记`tool_status=failed`，规划就绪或缺原图时记`not_invoked`。
