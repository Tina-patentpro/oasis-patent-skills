# TRIZ问题分析独立规则

## 问题与推导
从普通研发资料建立系统正常作用链、现象、工况、需求、硬约束及可干预原因；不能因没有F11品牌文件或T表就拒绝。根因区分观察、推导、假设及替代解释。技术矛盾需要证明改善一项确实恶化另一项；物理矛盾核同一对象参数的相反要求与条件。无矛盾仍分析问题，不强套TRIZ。
先核资源真实存在及可用条件，再选择工具线索。声称TRIZ推导的方向须有问题—模型—工具/线索—具体技术转化链；普通构思按真实来源标记，不事后贴标签。不复制第三方矩阵、教材或原理大全；本包只含获授权自编规则和通用方法名称。
## 方向、比较与验证
每个方向明确改变了什么、主体与对象、元实体/关系/手段/功能/效果、工作路径、资源、前提、替代与代价。按原问题回查是消除、缓解、折中还是转移矛盾，未验证不称已解决。相同机制换名称归为变体，互斥方向不得拼接，依赖前置条件的方案不能称独立可实施。
按共同目标/工况/基线/硬约束比较，给有条件推荐、暂缓理由及改变建议所需证据；数值不足不伪造排序。首个验证连接决定性未知、最小动作、资源/对照、观察和否定判据、继续/调整/暂缓条件。交T1、候选级T2/T3、矛盾表、方向卡及检索提示；完整路径、可推荐方向和成熟度分别判断，表齐不等于研发成功。

## 详细规则与自检

按[授权技术条款](business-rules.md)逐项核技术链、条件、范围、来源和对应成果；其中旧输入/历史治理不成为独立前置。交付前对照实际材料核所有重要对象、关系、数值、逻辑、实施路径、效果证据、支持/引用、人工改动、未读范围与全部开放警示。可在本次授权内修正生成遗漏，不能把本轮漏项推成用户缺件。自检、独立审阅、技术确认、专业接受、可提交各自留证，不用格式、分数或保存成功代替内容判断。

## 表字段

按[本节点技术表字段](table-contracts.md)组织实际职责内的T表/支持记录；不提前生产未到本节点的表，不填空表冒充完成。
