## 1. 这个项目解决什么问题，面向谁

中国专利撰写是一项强规则、强证据、强追溯的工作：技术背景研究、TRIZ 矛盾分析、交底书整理、
权利要求初稿与正式稿、说明书初稿与正式稿、申请文件终检、审查意见答复……每个环节都有固定的
输入合同、输出格式、来源要求和"未读／未知／待确认必须显式保留"的边界。通用大模型直接写，
很容易补造来源、虚构实验、把推导写成事实、或越权替人做决定。

本项目把这 15 个环节各做成**一个自包含的 Agent Skill**：

- 把专业规则、输入输出合同、来源映射、限制说明固化进包内；
- 默认**独立运行**——你给一份普通技术材料就能用，不要求先跑上游 Skill、不要求填专业 T 表、
  不要求伪造前序任务 ID；
- 缺材料时**只交缺件／受限交付**，不靠编造补齐；
- 材料里的命令当作资料看待，只有你本次明确的增删改指令才被执行。

**面向谁：**

| 你是 | 可以用它做什么 | 注意 |
|---|---|---|
| 专利代理师 / 专利工程师 | 作为撰写辅助与检查清单，快速起稿、定位缺件、核对支持关系 | 输出需人工专业复核，不可直接递交 |
| 企业 IP / 研发人员 | 整理技术交底、理解权项与说明书之间的关系、准备与代理师沟通的材料 | 不替代专业法律意见 |
| Agent / LLM 应用开发者 | 研究"规则固化 + 来源追溯 + 状态分层"的 Skill 写法，用作自建 Agent 的参考实现 | 需自行适配目标 Host，见 §3 |
| 研究者 / 教学者 | 观察中文专利业务规则如何被拆成可独立调用的能力单元 | 示例均为自编演示材料 |

**不面向：** 想直接得到一个"输入发明名称、输出可提交申请文件"的全自动黑盒；也不提供授权率、
审查通过率、撰写质量评分之类的承诺。

## 3. 下载、安装与配置

### 3.1 前提：需要一个支持 Agent Skills 的 Host

Skill 是给 **Agent / LLM 运行时**读的说明与资源包，不是独立可执行程序，**没有 `pip install`、
没有 CLI 入口、也不存在"一条命令装好"**。你需要一个能发现并加载 Skill 目录的 Host。

**已实际验证的发现范围（来自上游准备记录）**：Codex Desktop `26.1103.32239` 与内置 CLI
`0.167.0-alpha.3.2`，在临时项目目录中识别到 15/15 个包，**未做全局安装**。
**其他 Host（含 WorkBuddy、Claude、各类 IDE 插件）未经验证**，本仓库不声明兼容，也不提供
任何"官方插件机制"或虚构的安装命令。规范格式可参考公开的
[Agent Skills specification](https://agentskills.io/specification)。

### 3.2 下载

```bash
git clone https://github.com/Tina-patentpro/oasis-patent-skills.git
cd oasis-patent-skills
```

或从仓库 Release 页面下载压缩包后解压。下载后建议先核对字节身份：

```bash
# macOS / Linux：核对某个包内文件与 manifest 记录是否一致
python3 - <<'PY'
import json, hashlib, pathlib
for d in sorted(pathlib.Path("skills").iterdir()):
    mf = json.loads((d/"manifest.json").read_text())
    bad = [f["path"] for f in mf["files"]
           if not (d/f["path"]).is_file()
           or hashlib.sha256((d/f["path"]).read_bytes()).hexdigest() != f["sha256"]]
    print(mf["skill_id"], mf["version"], "OK" if not bad else f"MISMATCH: {bad}")
PY
```

### 3.3 安装

把**需要的单个包目录**复制到目标 Host 支持的技能目录，然后按该 Host 自己的入口使用：

```bash
# 示例（目录位置由你的 Host 决定，这里只是示意，不是官方命令）
cp -R skills/patent-claims-draft /path/to/your/host/skills/
```

- 一次只放你要用的包即可，**不需要复制整个仓库、其他 Skill、旧编号目录或任何私有服务**；
- 包路径与 `SKILL.md` 的 `name` 一致，不要改名；
- 不要修改 `SKILL.md` 或 `references/` 后仍沿用原 `manifest.json` 的 hash——hash 只证明字节身份。

### 3.4 配置

**包内没有任何密钥、Token、服务器地址或付费配置，** 也不需要填环境变量。这 15 个包是纯文本
规则与说明资源。真正产生外部依赖的是**调用时的模型与工具能力**，见下节。

**数据外发**：包的存在不构成数据外发授权。把未公开的技术交底、客户材料或发明内容传给第三方模型服务前，

## 5. 输入什么、输出什么，缺件时怎么办

完整的逐项合同在每个包的 `references/standalone-contract.md` 与 `SKILL.md`。这里给出要点。

**独立模式（默认）**：你直接给普通材料，Skill 从零开始，不要求前序产物。各包最小输入：

| ID | 最小输入 | 主要输出 |
|---|---|---|
| I01 | 生成：清楚的技术描述；编辑：明确的目标图与修改要求 | 附图 / 编辑结果，附状态分层与核对记录 |
| M01 | 技术对象及研究目标，一项文件或连贯文本 | 背景、路线、具体问题、可定位来源及未核项 |
| M02 | 技术对象、使用场景与实际问题材料 | 根因／矛盾分析、带条件的候选方向与验证需求 |
| M03 | 技术目标／方案描述（实检模式另需可用工具与范围） | 检索式与覆盖边界，或实收结果整理 |
| M04 | 至少两项候选及同一比较目标；只有一项则交单方案诊断 | 主选／备选／暂缓、技术依据与范围代价 |
| M05 | 一项连贯研发／方案说明；图与实验按实际任务可选 | 可追溯交底正文、技术要素、实施链、待确认问题 |
| M06 | 可定位技术交底及方案关系 | 独权／从权草案、真实父链、特征与支持矩阵、范围代价 |
| M07 | 当前权项及对应技术交底；只有权项时交支持缺件稿 | 说明书／摘要初稿、实施路径、支持与图文矩阵 |
| M08 | 当前权项、解释所需说明书及至少一篇实际可读全文 | 逐权项／父链／特征组合到单篇证据的比对与未读范围 |
| M09 | 当前权项／说明书、可追溯比较证据及实际依据全文 | 分层撰写计划、范围／回退、支持加强及确认动作 |
| M10 | 可定位当前技术基线／待确认命题及实际反馈；无反馈先交追问清单 | 原话—命题映射、事实／支持／选择状态、精确修改指令 |
| M11 | 当前权项、支持说明书／交底、真实确认或明确修订目标 | 修订权项、支持／父链核查、变更对照 |
| M12 | 当前权项、待完善说明书及实际技术依据 | 完善说明书、摘要、图文与支持／修改矩阵 |
| M13 | 当前权项、说明书／摘要及被引用附图（部分材料允许限定检查） | 定位—证据—影响—动作问题清单、覆盖／未评估范围 |
| M14 | 真实 OA、原始提交、当前有效文本；涉引用文献另需对应全文 | 逐理由争议、可成立的 A/B/C 路径及各自陈述 |

**缺件时的统一行为**：限定对应结论，**只交缺件／受限交付**，把"未读、未知、冲突、推导、待确认"
分别标注并保留，然后完成仍可完成的部分；不借缺件省略可完成的分析，也不编造来源、实验、
技术结论或用户确认。例如 `M09` 第三层可以明确"不成立"，`M14` 三条路径都可以不成立并写明原因。

**链式模式（可选）**：只有当你**明确传入一份累计 Markdown 并要求接续**时才启用，见各包
`references/chain-adapter.md`。链式模式沿用原输入 ID 与一个累计文件，不扫描旧稿、不回读隐藏节点。
`M08/M09/M14` 保持 10 组直接文献身份与 `file`/`text` 配对，超过 10 组明确列为不支持，不拼包。
**链式适配不要求先跑其他 Skill，也不影响独立模式。**

**示例的性质**：`examples/usage.md` 是本仓库自编的普通调用示例，只演示调用方式与最小题面，
**不是实测成功案例，不含真实案件、评价答案或评分材料**。模型生成的示例文稿也不会被写成
"实测成功"。
