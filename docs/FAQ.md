# 常见问题

这里回答两类主仓的试读问题：[oasis-patent-skills](https://github.com/Tina-patentpro/oasis-patent-skills) 提供按撰写环节组织的独立 Agent Skills，[oasis-dify-workflows](https://github.com/Tina-patentpro/oasis-dify-workflows) 提供专利业务 Dify 工作流的本地设计源。两者都是**实验性候选与设计源**，不是已验收的成品服务。

- 专利代理师／专利工程师：从 M05 交底整理入手，看输入输出合同与材料缺口如何处理。
- 企业 IP／研发负责人、专利所管理者：先看「不面向」、费用与数据边界，再决定是否交流部署与流程约束。
- Agent／Dify 开发者：按固定版本读文件结构、输入输出合同与依赖，在自有环境验证并反馈。

**想试读／反馈**：取固定版本 `2026.11.07-rc1`，按下面 Q2 的最短路线开始，问题发到对应仓 [Issues](https://github.com/Tina-patentpro/oasis-patent-skills/issues)／[Issues](https://github.com/Tina-patentpro/oasis-dify-workflows/issues)。
**想交流部署／咨询**：请通过[官网联系页](https://oasisintwrite.com/contact/)说明非敏感的组织类型、业务环节与部署约束；承接安排以双方实际确认为准。

**Q1｜我该先看哪个仓库、先试哪一个成果？**
A：想按环节试用独立 Skill，看 `oasis-patent-skills`；想研读 Dify 编排思路，看 `oasis-dify-workflows`。Skills 仓建议从 `M05 patent-technical-disclosure`（`0.3.0-rc.4`）开始，先读包内 `SKILL.md`、独立合同与 `examples/usage.md` 的调用请求示例；工作流仓建议先只读看 `Flow-1-1`（V1.0.2）的固定 YML 与同目录 `NOTES.md`。两份材料都从固定版本 `2026.11.07-rc1` 开始；这不是质量排名，也不代表有已落仓的场景讲解页。

**Q2｜怎么下载、怎么配置？有没有一条命令装好？**
A：从各仓 `2026.11.07-rc1` Release 下载，或用 `git clone` 后 checkout 同一 tag／固定 commit——不要默认 `main` 与 rc1 相同。用 `catalog.json` 核对逐项版本与 SHA-256。Skills 是给 Agent／LLM 运行时读的说明与资源包，不是可执行程序，没有 `pip install` 或 CLI 入口；把需要的单个包目录复制到你的 Host 支持的技能目录即可。工作流 YML 建议先只读审阅，要验证导入须在你能完全控制的独立 Dify 实例里做。

**Q3｜支持哪些 Host？WorkBuddy／Claude／各类 IDE 插件能用吗？**
A：本公开集合对其他 Host 的兼容性未验证。上游准备记录曾在 Codex Desktop `26.1103.32239`／内置 CLI `0.167.0-alpha.3.2` 的临时项目中识别 15/15 个包，未全局安装；这不证明业务验收。69/69 机械测试与 15 包完整静态校验属上游记录／发布检查记录，不是本轮重新执行。其他 Host 需要你自行适配与验证。兼容表若将来列出，须保留包版本与 manifest、Host 与版本、检查日期、发现／资源读取／执行／保存／工具各层、输入与结果证据及限制；缺字段写「未核」，不写成「官方支持」。

**Q4｜支持哪个 Dify 版本？能直接导入吗？**
A：未验证任何具体 Dify 版本的导入结果。12 份 YML 的 DSL schema 跨 `0.1.2`–`0.6.0`；12/12 只通过 YAML 语法解析（发布检查记录）。若要试，按 `docs/import-guide.md` 在隔离实例里做，缺模型／插件／环境变量／知识库引用时如实列缺件，不要删除必需节点换「看起来能导入」。

**Q5｜这 12 份 YML 就是已发布的那 12 个应用吗？**
A：不是。仓库公开的是本地维护的历史设计源，`catalog.json` 的 `asset_kind` 明示为本地设计源 YML、非实例发布导出；文件不含 App ID／发布版本 ID。历史上另有已在实例发布的应用记录，不等于本仓库文件，也不保证当前线上仍是同版。准确的实例发布导出是另一条尚未交付的技术线。

**Q6｜要花钱吗？你们提供免费模型接口吗？**
A：下载与使用仓库本身免费。模型推理、专利检索、图像服务由你自己的 Host／服务商提供，通常按量计费，费用由你与服务商结算。本仓库不含模型凭据、不提供免费公共推理接口，也没有把生产服务器地址写成默认配置。

**Q7｜现在能做什么、不能做什么？**
A：能——下载并核对字节身份、阅读规则与输入输出合同、按最短路线做无模型检查、在自有隔离环境复现与适配、提交具体反馈。不能——得到可直接递交的申请文件、得到授权率／通过率／节时承诺、把设计源当线上服务、在未验证的 Host／Dify 版本上宣称可用。输出一律需人工专业复核。
证据分层：上游有限记录保留两次图像调用及有限模式观察，尚未取得全 15 包的真实运行验收；对本公开集合的准确版本，新环境安装／导入验证、专业具名审阅与用户接受未取得，有限观察不证明所有包、Host 或工具模式通过。

**Q8｜`YOUR_API_KEY_HERE` 是什么？要不要填？**
A：`Flow-1-1` 第 330 行的 HTTP 请求头是发布时脱敏的占位值，不是有效凭据。使用该 HTTP 服务前需按服务要求配置自己的有效认证及其他依赖；本轮未验证导入或请求结果。对准确固定源／公开字节对的静态差异复核已完成，状态 `STATIC_ONLY`：945 行中只有第 330 行文本变化，解析对象唯一差异路径为 `/workflow/graph/nodes[3]/data/headers`，节点数、边数与图结构未变。这不代表导入必定成功、接口必定返回某种错误、当前凭据已撤销或服务仍可用；另有流程的 Dify 工具凭据模板引用需自行绑定。请勿把任何真实凭据提交到仓库或 Issue。

**Q9｜我把未公开的技术交底传给第三方模型，安全吗？**
A：包的存在不构成数据外发授权。把未公开技术交底、客户材料或发明内容传给第三方模型服务前，请自行确认该服务条款与你所在机构的保密要求。团队级部署与数据边界问题请走咨询入口，不要在公开 Issue 贴材料。

**Q10｜旧文档里的 ¥1／¥3／¥5 是现在的价格吗？**
A：不是。那是历史商业基线，不是当前报价，也不构成现行承诺。当前咨询与私有部署按具体范围洽谈，本仓库不设固定价格、不设闭源企业版、不承诺服务等级或效果指标。历史文件按已接受的公开范围原样保留。

**Q11｜怎样提交一个有用的反馈？**
A：请附资产 ID、集合 ref／包版本、manifest 或 YML SHA-256、Host 或 Dify 版本、非敏感最小输入及步骤、预期与实际、已做检查及脱敏证据；格式见对应仓 `CONTRIBUTING.md`。不要上传真实案件、客户交底或密钥，也不要只写「无法使用」。报错、日志、截图与证据路径同样须脱敏后再提交。

**Q12｜怎样参与贡献？现在有哪些可以认领的任务？**
A：可贡献问题报告、文档改进、新的独立用例或机械校验、规则／合同建议、导入兼容性观察；两仓 `CONTRIBUTING.md` 写明版本规则。合法新版本可以按新字节重新生成 manifest 并写入新版本身份；不得修改 expected hash 掩盖实际字节漂移，也不能让新 manifest 冒充旧版本原字节，旧版本的 manifest 与 expected hash 保持原样。目前没有经维护者发布的「可认领任务清单」或 `good first issue` 标签，不制造 Issue／标签凑活跃度。

**Q13｜有安全漏洞要私下报告，走哪里？**
A：目前尚未核准可用的私密举报渠道；GitHub 私密报告设置未核。两主仓无 `SECURITY.md` 只能证明缺该文件，不能证明平台私密漏洞报告功能未开启；账号公开邮箱为空也不构成对平台设置的核验。在渠道与设置核准前，请勿在公开 Issue 贴密钥、真实凭据或可利用细节；不编造邮箱，也不把商业顾问微信当成漏洞报告渠道。

**Q14｜怎样交流部署／咨询需求？**
A：团队收费服务与合作咨询请通过[官网联系页](https://oasisintwrite.com/contact/)说明需求；范围与价格另行确认，本仓库不设固定价格、不设闭源企业版、不承诺服务等级或效果指标，承接安排以双方实际确认为准。沟通前请说明非敏感的组织类型、所需业务环节与部署约束；可先提出本地／内网部署、模型选择、数据外发、权限隔离、日志与删除等要求，由双方进一步评估范围与验收证据。仓库公开或服务器本地部署本身不能证明模型请求不外发。详细技术材料不在公开 Issue 提交，公开 Issue 不收客户交底；漏洞类问题见 Q13，不要贴可利用细节。

**Q15｜我应该按哪个版本提问？**
A：请按 `2026.11.07-rc1` 固定 tag 或该 tag 下具体资产版本提问，并附 `catalog.json` 的文件名与 SHA-256（`M05` 集合内为 `0.3.0-rc.4`；`Flow-1-1` 为 V1.0.2、YML SHA-256 `c83d953e…`）。若从 `main` 或本地副本取文件，请在反馈中写明实际 ref／commit；`main` 不自动等于 rc1。两仓的 `NOTICE` 与来源说明请按仓库内对应文件的实际版本引用，不要默认 rc1 压缩包已包含这些文件。
