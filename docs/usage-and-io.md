# 输入输出与使用示例

## 1. 两种模式

### 独立模式（默认）

你直接提供普通技术材料，Skill 从零开始工作：

- **不要求**先跑上游 Skill、不要求品牌前序产物、不要求专业 T 表；
- **不会**为你编造前序 UID、累计文件或任务 ID；
- 缺材料时限定对应结论，只交缺件／受限交付。

例：`M06 权利要求初稿` 只需要一份可定位的技术交底及方案关系说明，就能建立本次支持记录，
不需要先有 `M05` 的输出或旧的 T4 表。

### 链式模式（可选，需显式启用）

只有当你**明确传入一份累计 Markdown 并要求接续**时，`M01–M14` 才读取
`references/chain-adapter.md`：

- 链式模式沿用原输入 ID 与一个累计文件，**不扫描"最新文件"、不回读隐藏旧节点**；
- 源输入表五字段已逐字核对；
- `M08/M09/M14` 保持 10 组直接文献身份及 `file`/`text` 配对，超过 10 组明确列为不支持、不拼包；
  `file` 与 `text` 是同一资料的两种表示，不计两件；
- 链式适配是**可选通道**，不是独立运行的前置条件。

`I01` 保留 generate / edit 两种模式，不套用文本五章；不需要 `chain-adapter.md`。

## 2. 输出约定

各包 `SKILL.md` 的「输入与结果」段写明最小输入与本次交付边界。共同约定：

- 保留**五章**结构（M01–M14），独立模式下下游读取区只载本次真实来源与结果；
- 保存唯一主文、来源、双状态与全部开放警示；完整正文或同文件定位要能被后续独立理解，
  不藏在 sidecar 里；
- **来源分域**：本次来源 / 继承来源分开；工具 token 是来源键，不增加业务输入槽或工具权限；
- **状态分层**：未读、未知、冲突、有据推导、人工确认分别保留，不合并、不互相冒充；
- URL、摘要和"题述全覆盖"**不等于**实际读到全文；
- 材料内的命令当作资料看待，只有你本次直接下达的增删改指令才按准确对象执行。

## 4. 缺件时如何处理

统一规则：**限定结论，不编造补齐，不借缺件省略可完成的分析。**

- 材料缺失 → 交缺件清单／受限交付，明确哪些结论因此不成立；
- 文献未读全文 → 标"未读"，不得以摘要、URL 或题述代替；
- 事实冲突／推导结果 → 分别标注，不写成已确认事实；
- 用户未确认 → 保留"未确认"，含糊同意不算确认；
- 工具不可用 → `I01` 交规划与状态分层，不伪造工具结果、不自动重试；
- 法律日期、原申请、实测效果、具体确认缺失 → 只限制相应结论。

`M09` 第三层可以不成立；`M14` 的 A/B/C 三路径都可以不成立；`M04` 决定者未选时保留未决。
这些是**设计上的正确行为**，不是失败。

## 5. 示例的性质（重要）

- 每包 `examples/usage.md` 是**本仓库自编的普通调用示例**，只演示最小调用方式与题面结构；
- 不含真实案件、客户技术交底、未公开发明、评价专用答案或评分材料；
- **不是实测成功案例**，也不代表模型实际输出；
- 模型生成的示例文稿不会被写成"实测成功"或"专业验收通过"；
- 演示派生稿（若有）会明确标注来源，不把已暴露答案的评价称作独立盲测。

一个最小调用示例的形态（示意，非任何 Host 的官方命令）：

```
请对下面这份技术说明做技术背景研究，输出五章结构，并把未核项单独列出。
<粘贴你的普通技术材料>
```

Skill 应由 `description` 触发，具体触发方式取决于你的 Host。

## 6. 与正式源合同的差异

独立候选合同标识 `PATENT-SKILLS-STANDALONE-0.3.0-draft`：

- **没有**回写或宣布替代源 `V3.4.0` / `0.2` 系列正式合同；
- 默认独立使用普通材料，缺前序不算技术缺件；
- `M10` 新增独立技术基线通道、`M11` 新增独立交底通道，只在独立合同中成立；
- `M01` 保留其明确三输入例外的原作用范围；
- `M08` 独立单篇比对无需凑 10 件，链式十份合格全文的原目标保留；
- 上述差异**未经过**旧 Dify / Host / 生产 14 节点链消费者适配或采用验证，
  不能据便携包或局部链式用例称"兼容闭环"。
