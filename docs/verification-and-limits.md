## 2. 本次发布实际执行了哪些检查

- 逐包重新读取 `当前Skills清单.json` 与 `候选目录索引.md`，按**具名索引**精确选版，
  没有按最高版本、目录名或修改时间挑选；
- 逐包比对 `manifest.json` 内每个 `path` 的 `bytes` 与 `sha256` 和实际文件；
- 检查 `SKILL.md` 的 YAML frontmatter、`version`、`license`、`business-id`；
- 逐文件扫描：`/Users/` 等本机绝对路径、Windows 用户目录、内网/服务器地址、
  `sk-` 形式密钥、`Bearer <长串>`、凭据赋值、SSH 私钥块；15 包均 0 命中；
- 确认包内引用自包含（无父目录引用、无符号链接、无自动下载依赖）；
- 复制后重算发布副本 hash，与源包逐字节一致（本次 Skills **无任何字节改动**）。

**未执行的验证**（不因文件整理完成而推定）：安装／导入、跨 Host 加载、真实模型调用、
工具链闭环、专业质量评审、用户接受、生产链路兼容。

## 4. 状态用语的含义

| 用语 | 含义 |
|---|---|
| `base-candidate` / 基础候选 / 实验性候选 | 已整理的候选包，静态与机械检查通过，但**未**完成运行、专业与用户接受 |
| `PREPARED_NOT_PUBLISHED` | 上游准备记录的状态；本次已公开发布，**成熟度仍是候选**，不等于验收通过 |
| 导出可解析 | 文件语法／结构可解析，与能否导入、能否运行无关 |
| 已在 JTTI 发布 | 指 2026-11-04 工作室实例上的应用发布状态，**与 Skills 包无关** |
| 新环境导入成功 | 本次**未**验证 |
| 真实运行成功 | 仅上游记录中的有限观察，不是全 15 包验收 |
| 专业接受 | 未取得 |

> 特别提醒：工作流在 Dify 实例上线、DSL 可解析，都**不能**转成 Skills 的运行证据；
> Skills 的机械测试通过也不能推定 Dify 工作流通过。两套资产分别保留自己的测试结果。

## 5. 使用建议

- 把它当作**规则参考与撰写辅助**，输出必须经具备资质的人员复核；
- 先在非生产材料上验证你的 Host 能否正确加载与遵守包内合同；
- 不要用于直接生成可递交文件，也不要据此作法律结论；
- 发现问题请按 [CONTRIBUTING.md](../CONTRIBUTING.md) 的格式提交 Issue，附 Skill ID、版本、
  Host、最小输入、预期与实际、证据路径。
